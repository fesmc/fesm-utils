coords

Coordinates, projections, and grid-to-grid remapping

Overview

coords is the geometry and remapping core of fesm-utils. It is a clean rebuild of the older coordinates library, keeping the user-facing API (points_class / grid_class / map_class, *_init, map_field) while replacing the internal storage, neighbour search and conservative remapping with a single design. Everything is reached through one umbrella module:

use coords

The package covers:

  • Coordinate and grid definition — point sets (points_class) and regular grids (grid_class), each carrying a shared coordinate-system descriptor (coord_system: map type, units, planet, projection).
  • Map projections — the oblimap2 oblique stereographic forward/inverse transforms, driven by projection parameters (lambda, phi, alpha, x_e, y_n) (for polar_stereographic, phi is the standard parallel and the projection is centred at the pole, on a sphere as on an ellipsoid), and transverse Mercator (e.g. UTM; mtype="transverse_mercator", Snyder 1987) with lambda the central meridian, phi the latitude of origin, k0 the scale factor and x_e/y_n the false easting/northing [m].
  • Gaussian-latitude grids — quadrature latitudes for spectral/atmospheric grids (non-uniform y-axis).
  • k-d tree nearest-neighbour search — the fast neighbour engine underneath distance-based maps.
  • Weight-map remapping — one sparse source→target store applied with nearest-neighbour, Shepard (inverse-distance), quadrant, bilinear or conservative (area-weighted) kernels.
  • SCRIP-superset weight-map file I/O — maps are cached as valid SCRIP remapping files, interoperable with cdo and other tools.
  • CDO grid-description interop and cached map generation — read/write cdo griddes files, generate weights online (in-package or via an external cdo call), and load-if-exists / save-on-generate caching.
  • The multigrid coupler — a thin registry + lazy map-cache layer for remapping fields between many named grids.

Key derived types

All types are defined in coordinates.f90 (geometry) and mapping.f90 (maps), and re-exported by use coords.

Type Role
coord_system Coordinate-reference metadata (mtype, units, planet, proj, xy_conv, is_cartesian, is_projection, is_lon180). Defined once and embedded as %cs in every geometry type.
points_class An unstructured set of points: npts, 1D arrays x, y, lon, lat, area, and %cs.
grid_axis_class Regular axis description: nx, ny, x0, dx, y0, dy, the axis vectors x(:), y(:) (supports explicit non-uniform axes, e.g. Gaussian latitudes) and the cell edges x_bnds(0:nx), y_bnds(0:ny). The edges are filled at grid_init (default: adjacent midpoints, half-cell extrapolation at the ends, axis_midpoint_bounds; explicit_bnds records given bounds) and are the one source of cell edges for grid_area and the conservative generators.
grid_class A regular grid: name, axis block %G (grid_axis_class), 2D arrays x, y, lon, lat, area, and %cs.
map_class Public map wrapper: source/target names (name1, name2), target coordinate system %cs, target axes %G, fixed interpolation method, and the internal weight store %wm.
weight_map_t The single sparse source→target store (link-centric, SCRIP-style). Usually accessed only through map_class; see below.
coupler_class A registry of named grids plus a lazily-built cache of grid→grid maps (coupler.f90).

The weight store

weight_map_t (module weight_map) is one sparse matrix with two payload flavours, selected by %kind:

  • MAP_DISTANCE — links carry the neighbour distance, position (xn, yn) and quadrant; the per-link weight is built at apply time from the chosen kernel. One cached distance map therefore serves nn / quadrant / shepard / bilinear and adapts to a time-varying source mask.
  • MAP_WEIGHT — links carry a final baked weight w(:); apply just reduces it (conservative maps, imported SCRIP maps, or precomputed bilinear).

Links are grouped by destination; dst_off(:) is a CSR offset array. The type is rarely handled directly — map_init / map_field wrap it — but the low-level API (weight_map_alloc, weight_map_index, weight_map_apply, weight_map_prune, weight_map_free) is public for building custom maps.

Core workflow

The typical use is: define a source and target grid, generate (or load) a weight map between them, then apply that map to remap one or more fields.

use coords

type(grid_class) :: gsrc, gtgt
type(map_class)  :: map
real(dp), allocatable :: field_src(:,:), field_tgt(:,:)

! 1. Define source and target grids (here two Cartesian grids in km).
call grid_init(gsrc, name="src", mtype="cartesian", units="kilometers", &
               x0=0.0_dp,   dx=100.0_dp, nx=10, y0=0.0_dp,   dy=100.0_dp, ny=10)
call grid_init(gtgt, name="tgt", mtype="cartesian", units="kilometers", &
               x0=150.0_dp, dx=100.0_dp, nx=7,  y0=150.0_dp, dy=100.0_dp, ny=7)

! 2. Generate (or load) a weight map. `method` fixes the kernel; the map is
!    cached under `fldr` and reloaded next time when load=.true. (the default).
call map_init(map, gsrc, gtgt, method="shepard", max_neighbors=8, fldr="maps")

! 3. Apply it. var1 is the source field; var2 is sized to the target grid.
allocate(field_src(10,10), field_tgt(7,7))
! ... fill field_src ...
call map_field(map, "myfield", field_src, field_tgt, stat="mean")

grid_init is generic and also accepts explicit axis vectors (x=, y=), an existing grid/points object, or a file (grid_init(grid, filename, ...) reads a .nc grid or a /map/ namelist). Explicit cell bounds can be given with x_bnds= / y_bnds= (0:n, validated: strictly monotonic, each centre inside its cell; the other axis takes the default midpoint bounds). For a lat-lon or Gaussian grid with explicit bounds, grid%area is the latitude-band area (R²·Δλ·(sin φ₂ - sin φ₁) on a sphere, the authalic zone formula on an ellipsoid); grids with default bounds keep the 4-corner area.

grid_init_gaussian(grid, name, nlon, nlat [, planet, lon180, x0]) builds a global Gaussian grid (mtype="gaussian") whose latitude bounds come from the Gauss weights, sin φ_{j+1/2} = sin φ_{j-1/2} + w_j from -1 to +1: the bands reach the poles, each node lies inside its band, and the cell area is the quadrature weight R²·Δλ·w_j. planet defaults to "Spherical Earth" here (spectral models, SHTns, are spherical); other grids default to WGS84. A lat-lon → Gauss con map then integrates exactly in the quadrature: Σ_k Δλ·w_j·v_k equals the band-metric source integral, with no rescaling. grid_cdo_write_desc_short writes the bounds of such a grid as cdo xbounds/ybounds, and grid_cdo_read_desc reads them back (only from files with the fesm-utils header; existing descriptions read as before). Point sets are built the same way with points_init(pts, name=, mtype=, units=, x=, y=, ...).

map_init is overloaded for grid→grid, grid→points, points→grid, points→points, and grid→grid by name (map_init(map, name1, name2, ...), which reads both grid descriptions from grid_<name>.txt). Key optional arguments to the grid→grid form:

  • method — interpolation kernel: "con" (conservative) or a distance kernel "nn" / "shepard" / "quadrant" / "bilin" (default "nn").
  • gen — generator used when weights must actually be built: "coords" (in-package, default) or "cdo" (external cdo system call).
  • fldr — map cache directory (default "maps").
  • load — if .true. (default) an existing cache file is loaded instead of regenerated; freshly generated maps are always saved.
  • max_neighbors, dist_max — neighbour-search controls for distance maps.
  • precompute_weights — collapse a distance store to baked weights at init for shepard/bilinear (default .true.); the on-disk cache stays distance-format either way.
  • weight_cutoff — relative cutoff for pruning sliver links from baked (con/bilinear) maps before caching: per target, links below weight_cutoff·max(w) are dropped (default 1e-4; 0.0 keeps all links). The largest link of a target always survives; the coverage removed is kept (see Normalisation and coverage).
  • on_mismatch, hash_names — cache identity, see CDO interop and map caching.

map_field is generic over the field element type (integer, sp, dp) and over grid/points sources and targets. Beyond stat it accepts method (kernel override for distance maps), missing_value, radius, mask2, reset, mask_pack, and optional fill/filter post-processing (fill_method, filt_method, filt_par). The stat argument selects the reduction over each target’s links: "mean" (default), "count" (weighted mode), or "stdev". The 8 real specifics also take norm, frac2, area1 and area2 (below).

Normalisation and coverage

A conservative map made by the coords generator carries, besides its link weights w_jk (overlap area in the map metric of the generator), the full cell areas of source and target (wfull_src, wfull_dst) and the link sums before pruning (wcov_src, wcov_dst), all in that metric; they are written to the cache as mp_wfull_*, mp_wcov_*. With them, for target k and its valid links V_k (w > 0, source value not missing), and φ_jk = q_j·w_jk/wfull_src_j the fraction of source cell j lying in k (q, r restore what pruning removed):

Argument Value at target k
frac2 (real(dp), target shape) covered fraction min(1, r_k·Σ_V w / wfull_dst_k); 0 where nothing valid is linked, outside mask_pack, or not mapped
norm="frac" (default) Σ_V w v / Σ_V w: the covered mean (unchanged path)
norm="dst" r_k·Σ_V w v / wfull_dst_k = frac2·mean (map metric)
norm="dst", area1 + area2 Σ_V φ_jk·area1_j·v_j / area2_k, exact in the model metric
norm="sum" Σ_V φ_jk·α_j·v_j, α = area1 if present, else 1 (amount per target)

area1 (source shape) and area2 (target shape) are the model cell areas (real(dp)). With norm="dst" and both areas, Σ_k area2_k·v2_k = Σ_j area1_j·v_j·Σ_k φ_jk for any choice of areas: for a target that covers the source, the integral is preserved. Rules: norm /= "frac" needs stat="mean" and a conservative map (else an error); frac2 on a non-conservative map is merge(1,0,mask2); area1 without area2 (or the reverse) with norm="dst" is an error; fill/filter post-processing does not change frac2. A con map without coverage data (a cdo map, or a cache file written before coverage was stored) stops with “regenerate ” when norm or frac2 is requested. The 4 int specifics take none of these.

Geometry of conservative_spherical (projected source → lat-lon/Gauss target). Each cell edge is subsampled into NSUB = 8 segments in the grid’s own plane (projection x-y, or rotated lon-lat) and every sample is inverse-projected and joined by great-circle arcs, so a projected cell that straddles the 0/360 meridian or contains the pole is a proper spherical polygon. A target cell’s poleward parallel, traced by great-circle chords, is concave, so the source polygon is clipped against the cell’s 8 strips in longitude (each convex, bounded by two meridians and one chord of each parallel) and the pieces are summed; the strips of all target cells tile the sphere. Target longitudes come from the unwrapped axis (as in the lat-lon → lat-lon path) and latitude bounds are clamped to ±90. For a target that covers the source domain, Σ_k φ_jk = 1 to ~1e-12 on a spherical planet (up to ~2e-10 for a cell that holds the pole, round-off over its ~1500 polar strip pieces) and to ~1e-8 on WGS84 (the pieces have great-circle edges, and their geodesic areas on the ellipsoid do not add up exactly). Each source polygon is built once (source-major loop over a k-d tree of the target centres); polygons with repeated vertices (a cell with two corners at a pole) are reduced to distinct vertices, candidate pairs whose bounding spherical caps do not meet are not clipped, and a source polygon that lies inside one strip takes its own area as the overlap. The links of each target are stored in ascending source order for any thread count. ANT-16KM → T64 (WGS84): 4.3 s serial, 0.8 s on 10 threads.

Remapping kernels

The kernel is fixed when the map is generated (it is part of the cache key) and selected via method:

  • nn (nearest) — copies the single nearest valid source value. Use for categorical/index fields, masks, and where no smoothing is wanted.
  • shepard — inverse-distance-squared weighting over the neighbours within radius. A good general-purpose smooth interpolation for scattered or point-set sources.
  • quadrant — nearest valid neighbour in each of the four quadrants, IDW combined; more isotropic than plain Shepard near data gaps.
  • bilin (bilinear) — for structured source→target pairs, exact index-space bilinear interpolation (matches cdo genbil). Best for smooth fields on regular grids; bakes to a MAP_WEIGHT map.
  • con (conservative) — area-weighted overlap via analytic polygon clipping. Conserves the area integral, so it is the right choice for fluxes and for aggregating a fine grid onto a coarse one. Built as a MAP_WEIGHT map.

Distance kernels (nn/shepard/quadrant) share a single MAP_DISTANCE store, so the kernel can also be overridden per call in map_field(method=) without rebuilding the map. Conservative and bilinear are baked weights and are fixed at generation.

CDO interop and map caching

Grids round-trip through cdo griddes text files (module grid_cdo):

  • grid_cdo_write_desc_short(grid, fldr) writes grid_<name>.txt, a cdo-compliant description with a #-comment header carrying the full coord_system so the grid can be reconstructed exactly.
  • grid_cdo_read_desc(grid, name, fldr) rebuilds a grid_class from such a file (the reader falls back on the CF grid_mapping_name for files stripped of the fesm-utils header, e.g. native cdo descriptions).

Map caching is handled inside map_init. The cache filename is derived from the two grid names, the folder and the method (gen_map_filename), and:

  1. if load=.true. (default) and the file exists, the map is loaded, with the file format auto-detected — an in-package cache (carries a meta variable) vs a standard/cdo SCRIP file;
  2. otherwise the weights are generated (in-package for gen="coords", or by an external cdo gen<method> call for gen="cdo") and saved to the cache.

Cache identity. Each new cache file (in-package or cdo) carries global attributes coords_src_sig, coords_dst_sig (grid signatures: grid_signature_str(grid), the coordinate system, the axis sizes and the first/last/sum of the axes and bounds), coords_method, coords_gen, coords_weight_cutoff and coords_format. On load (map_init with a cached file), the file is checked against the grids:

  • signatures present and different (grid_signature_match, tolerance 1e-9 of a cell, so a grid read back from grid_<name>.txt still matches): on_mismatch="error" (default) stops and names both signatures and the file; on_mismatch="rebuild" regenerates and overwrites the file (logged);
  • no signatures (a file written before signatures, or by another tool): loaded as before, with a one-time “unverified” log line;
  • n_src / n_dst that do not match the grid sizes always stop.

By default the file name stays scrip-<method>_<src>_<dst>.nc. With map_init(..., hash_names=.true.) (or coupler_init(..., hash_names=.true.)) it is scrip-<method>_<src>-<h8>_<dst>-<h8>.nc, where h8 = grid_hash8(grid) (FNV-1a over the signature at 6 significant digits), so two grids with one name can coexist in one folder. A legacy file of the same size but other axes is accepted unverified: clear the map folder (or rename the grid) when a grid definition changes at equal size.

Because the cache is always a valid SCRIP remapping file, a cdo-generated map and an in-package coords map interoperate at the same filename. The file I/O primitives are public as weight_map_write / weight_map_read (module map_io); map_read(map, src_name, dst_name, fldr, method) loads a pre-existing SCRIP map directly into a map_class.

Coupler

The coupler module (module coupler, use coupler) sits on top of the mapping core and manages many grids at once. A coupler_class holds a registry of named grids and a lazily populated cache of grid→grid maps: grids are nodes, maps are directed, method-typed edges.

use coords
use coupler

type(coupler_class)   :: cpl
type(grid_class)      :: gcoarse, gfine
real(dp), allocatable :: fs(:,:), ft(:,:)

call coupler_init(cpl, map_fldr="maps")          ! empty registry + cache
                                                 ! [, gen, on_mismatch, hash_names]
call coupler_add_grid(cpl, "coarse", gcoarse)    ! register grids by name
call coupler_add_grid(cpl, "fine",   gfine)

! remap sizes the destination itself; the (src,dst,method) map is built on first
! use and reused thereafter. method defaults to "con".
call remap(cpl, fs, "coarse", ft, "fine", method="bilin")
  • coupler_add_grid(cpl, name, grid) registers a copy of a grid (once, at init); coupler_take_grid(cpl, name, grid) moves an allocatable grid in without a copy (for very large grids). Unregistered names are resolved on demand from grid_<name>.txt in the map folder, read once into a “from disk” slot and reused. Registering a name that is already a from-disk slot is a no-op if the grids agree and an error otherwise.
  • remap(cpl, var_src, src, var_dst, dst, method, stat, missing_value, mask2, reset, mask_pack, fill_method, filt_method, filt_par, norm, frac2) finds-or-builds the map for (src, dst, method), allocates var_dst to the target size, and applies it with map_field, to which the optional arguments are passed unchanged. It is overloaded for dp / sp / int and 2D / 3D fields (the int specifics take missing_value, mask2, reset, mask_pack; for 3D, mask2 and frac2 are 3D and the map is applied per layer). With reset=.false., var_dst must already be allocated at the target shape. method is part of the cache key; stat and the rest are forwarded per call and are not.
  • method="auto" resolves per call: "con" for norm="dst"/"sum" (amounts are remapped conservatively both ways); otherwise "bilin" when the target is finer than the source (smaller median model cell area, i.e. refining) and "con" when it is coarser or equal. The model cell area is the plane dx·dy for a projected grid and grid%area·xy_conv² otherwise.
  • remap with src == dst copies the field (no map, no registration needed): mask_pack, reset, fill_method and filt_* still apply, mask2 is var /= missing_value, and stat="stdev" gives 0.
  • coupler_method(cpl, src, dst [, method, norm]) returns the method remap would use for the same arguments ("auto" resolved) without building or applying a map, e.g. to log it.
  • coupler_prime(cpl, src, dst, method, gen) eagerly builds a map up front (fail-fast at init rather than mid-timestep) and is the point at which a map’s generator can be overridden via gen=. It is a no-op for src == dst.

Global ↔︎ regional exchange

Each registered grid carries a model cell area [m²], the area its model integrates over: by default the plane dx·dy for a projected grid (what Yelmo and FastIsostasy integrate) and grid%area·xy_conv² otherwise. coupler_set_area(cpl, name, area) overrides it (e.g. the Gaussian quadrature R²·Δλ·w_j of a spectral model). remap with norm="dst" / "sum" passes the registered areas of both grids as area1 / area2, so mass accounting and the integral below share one metric per grid (an identity remap with norm="sum" returns v·area).

  • coupler_integral(cpl, name, var [, mask, missing_value, describe]) returns Σ area·var (Neumaier-compensated) with the registered areas; with describe=.true. it logs this integral next to the one over the ellipsoidal cell areas (grid%area), as a diagnostic of the metric difference (several % for a polar stereographic ice grid). For a regional → global remap with norm="dst", the global integral equals the covered part of the regional one to rounding.

  • Merge of N regional fields and a background onto a global grid, in accumulator form:

    type(coupler_merge_t) :: acc
call coupler_merge_begin(acc, cpl, "T64" [, kind="extensive"|"intensive"])
call coupler_merge_add(acc, cpl, "ANT", h_ant [, owner=o_ant, missing_value=])
call coupler_merge_add(acc, cpl, "GRL", h_grl [, owner=o_grl])
call coupler_merge_end(acc, cpl, background, h_glob [, frac_tot=, overlap_tol=])

    Per domain d (valid cells j, owner weight o_dj, default 1) and target cell k: coverage F_dk = r_k Σ_j w_jk o_dj / wfull_k; amount A_dk = Σ_j φ_jk o_dj area_j v_j / area_k (extensive) or r_k Σ_j w_jk o_dj v_j / wfull_k (intensive). With F = Σ_d F_d: extensive var = (1 - min(F,1))·bg + Σ_d A_d (regional amounts are never rescaled; only the background is capped), intensive var = (1 - min(F,1))·bg + Σ_d A_d / max(F,1) (preserves a constant). Domains are summed in the order of their names, so the result does not depend on the order of coupler_merge_add calls; adding a domain twice is an error. max(F) > 1 + overlap_tol (default 1e-2) stops and names the overlapping domains; a smaller excess is accepted and the double-counted amount logged.

  • coupler_owner_reduce(cpl, src_hi, owner_hi, dst, owner) removes from owner (on dst) the part already owned by the higher-priority domain: owner := max(0, owner - covered fraction of owner_hi). Call it once at init, in priority order, to make Σ_d o_d = 1 where domains overlap.

  • coupler_split(cpl, src, var_src, dst, var_dst [, method, ref_src, ref_dst, missing_value, fill_method, mask2]): global → regional. Without references it is remap (default method="bilin"); with both, var_dst = ref_dst + remap(var_src - ref_src), where a missing anomaly counts as 0 (the reference is kept). One reference without the other is an error.

Each map is built once, stored once, and shared across all callers. Grids and maps live in allocatable slot arrays without a fixed capacity: when an array grows, each slot’s grid / map is moved (move_alloc), never copied, and maps are built directly from the registered grids.

Bit-identity gate

test/coords/test_coupler_bitident.f90 runs a fixed call set of the coupler and map_field (con/bilin/nn; dp/sp/int; stat variants; reset=.false., mask_pack, fill/filter; 3D; grid ↔︎ points; every conservative generator path) and writes each result, the grid geometry and the map weights to bitident_out/<case>.bin. make check runs it for its in-binary checks (remap = direct map_field). To compare against a reference commit:

test/coords/bitident.sh <ref-commit>               # gen + cached
BITIDENT_MODES=cached test/coords/bitident.sh <ref> # across a change of new maps

The script builds the working-tree copy of the test at <ref-commit> (in a temporary git worktree, with the compiler block of the current root Makefile) and at the working tree, and compares every stream with cmp: gen (maps generated by each build) and cached (both load the cache files the reference generated).
